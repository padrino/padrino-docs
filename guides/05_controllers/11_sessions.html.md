# Sessions

_Kindly borrowed from Sinatra's docs :)_

A session is used to keep state during requests. If activated, you have one
session hash per user session:

```ruby
enable :sessions

get '/' do
  "value = #{session[:value].inspect}"
end

get '/:value' do
  session[:value] = params[:value]
end
```

Note that `enable :sessions` actually stores all data in a cookie. This might
not always be what you want (storing lots of data will increase your traffic,
for instance). You can use any Rack session middleware by passing it to the
`sessions` setting:

```ruby
set :sessions, use: Rack::Session::Pool, config: { same_site: :lax, expire_after: 2592000 }

get '/' do
  "value = #{session[:value].inspect}"
end

get '/:value' do
  session[:value] = params[:value]
end
```

With `use:`, cookie options such as `same_site` and `secure` go in `config:`.
`Rack::Session::Pool` keeps sessions in the memory of one process, so with Puma
workers, several Falcon processes or several servers, use a store they share.

To improve security, the session data in the cookie is signed with a session
secret. A random secret is generated for you by Sinatra. However, since this
secret will change with every start of your application, you might want to set
the secret yourself, so all your application instances share it:

```ruby
configure :production do
  set :session_secret, ENV.fetch('SESSION_SECRET')
end
```

Projects generated with Padrino 0.18.0 or later already read `SESSION_SECRET`
in `config/apps.rb`, with a fallback value generated with the project for when
it isn't set. Don't rely on that committed value in production:

```ruby
set :session_secret, ENV.fetch('SESSION_SECRET') { '...' } # the generated value
```

Older projects set only a random one there. The secret must be at least 64
bytes long. Generate your own with `padrino rake secret`, or:

```bash
$ ruby -rsecurerandom -e 'puts SecureRandom.hex(64)'
```

If you want to configure it further, you may also store a hash with options in
the `sessions` setting:

```ruby
set :sessions, domain: 'foo.com'
```

To share your session across other apps on subdomains of foo.com, prefix the
domain with a `.` like this instead:

```ruby
set :sessions, domain: '.foo.com'
```

## Cookie flags

The same hash sets the cookie's `SameSite` and `Secure` attributes:

```ruby
set :sessions, same_site: :lax, secure: true
```

Use `set :sessions` in place of `enable :sessions`, not after it: a later
`enable :sessions` sets the setting back to `true` and drops the options.

`same_site` takes `:lax`, `:strict` or `:none`. Apps generated by Padrino use
`same_site: :lax`. Browsers drop a `same_site: :none` cookie unless it is also
`secure: true`. The cookie is also `HttpOnly` by default.

`secure: true` tells the browser to send the cookie only over HTTPS. Rack also
skips saving the session when it sees a plain HTTP request, so over HTTP every
request starts with an empty session, and logins and CSRF tokens stop working.
Turn it on only where the site is served over HTTPS. Apps generated by Padrino
turn it on in production:

```ruby
set :sessions, same_site: :lax, secure: Padrino.env == :production
```

If a proxy or load balancer handles TLS and talks to the app over HTTP, it must
send the `X-Forwarded-Proto: https` header so that Rack sees the request as
HTTPS. A production app served over plain HTTP, such as `padrino s -e production`
on your own machine, needs `secure: false`.

The apps of a project share one session cookie, so give each of them the same
`secure:` setting: an app without it rewrites the cookie without the flag.

## Flash Messages

The flash carries a short message, such as "Post was created.", over to the
next request, usually the page you redirect to. It is kept in the session, so
the app needs sessions turned on; apps generated by Padrino have them. Without
sessions, messages set for the next request are dropped without an error.

```ruby
post :create do
  @post = Post.new(params[:post])
  if @post.save
    flash[:notice] = 'Post was created.'
    redirect url(:posts, :index)
  else
    flash.now[:error] = 'Post could not be saved.'
    render 'posts/new'
  end
end
```

`flash[:notice] = '...'` sets a message for a later request. It stays in the
session until a request uses the flash (reads it, sets a message or calls
`flash_tag`): that request sees it, and later ones don't. A request that never
touches the flash, such as a JSON endpoint or a missing page, leaves it
waiting, and a request that only sets a new message drops the waiting one
without showing it. Reading `flash[:notice]` returns the message that arrived
with the current request, so a message you set is not visible until a later
one.

`flash.now[:error] = '...'` sets a message for the current request only, for a
page you render instead of redirecting. It works without sessions.

`redirect` also takes the messages as a hash, after the URL or after a status
code:

```ruby
redirect url(:posts, :index), notice: 'Post was created.'
redirect url(:posts, :index), 301, notice: 'This page has moved.'
```

In this hash, a symbol is translated with `I18n.translate`, so
`notice: :post_created` shows the translation of `post_created` (a missing key
shows I18n's "Translation missing" text). `flash[:notice] = :post_created`
stores the symbol as it is.

To change what reaches the next request:

- `flash.keep` passes all the messages of the current request on to the next
  one, and `flash.keep(:notice)` passes only that one.
- `flash.discard` drops the messages set for the next request, and
  `flash.discard(:notice)` drops only that one.

`flash.notice = '...'`, `flash.error = '...'` and `flash.success = '...'` are
shortcuts for `flash[:notice] = '...'` and so on. To show the messages in a
view, use `flash_tag`, one of the
[asset helpers](/guides/application-helpers/asset-helpers "asset helpers"):

```haml
= flash_tag(:notice, :error)
```
